# openwrt-pbr-vpn: управление раздельным туннелированием на OpenWrt с автоматическим обходом ТСПУ

## Проблема

Российские интернет-провайдеры обязаны устанавливать оборудование ТСПУ (технические средства противодействия угрозам) — аппаратно-программные комплексы глубокой инспекции пакетов, которые работают на уровне транзитного трафика. Классическая блокировка по IP уже давно стала лишь первым эшелоном: ТСПУ умеет анализировать сигнатуры протоколов, отслеживать состояние соединений и применять избирательные ограничения — например, пропускать WireGuard-рукопожатие, но глушить канал данных.

Поднять полный VPN-туннель на роутере — очевидное решение, но оно приносит свои издержки: весь трафик домашней сети идёт через удалённый сервер, латентность растёт для всего, включая российские ресурсы и локальные сервисы, где VPN только мешает. Более разумный подход — **split-tunnel**: заблокированные сервисы идут через VPN, всё остальное — напрямую.

Именно эту задачу решает **openwrt-pbr-vpn**.

## Архитектура

Инструмент работает на хост-машине (ноутбук, сервер, Raspberry Pi) и управляет роутером через SSH. На роутере не нужен никакой агент — используется стандартный dropbear, без SFTP. Маршрутизация реализована через nftables: множество IP-адресов заблокированных доменов поддерживается актуальным и используется для policy-based routing в nft.

Ключевые компоненты:

- **DoH-резолвер** — периодически резолвит домены заблокированных сервисов через DNS-over-HTTPS и обновляет nft-множество на роутере без зависимости от провайдерского DNS.
- **Прокси подключения** — работает через SSH с обычным dropbear; никакого дополнительного ПО на роутере не требуется.
- **Демон-сторожевой пёс** — работает в фоне, следит за качеством активного VPN-пира и переключается на следующий при деградации.
- **Web UI** — Next.js-интерфейс с live-графиком трафика, панелью зондирования эндпоинтов в реальном времени, просмотром логов и настройками.

Поддерживаются WireGuard и OpenVPN.

## Детекция блокировки ТСПУ: как это работает

Это наиболее нетривиальная часть инструмента. Проблема в том, что ТСПУ может пропускать WireGuard-хендшейк целиком — туннель поднимается, `wg show` показывает `latest handshake`, но данные не проходят. ICMP-пинги через туннель тоже не помогают в диагностике на этапе зондирования.

Решение — **счётчики байт интерфейса**. Зонд отправляет трафик через туннель и на коротком временном окне измеряет дельту `tx_bytes` и `rx_bytes` на WireGuard-интерфейсе. Если TX растёт, а RX остаётся около нуля — это характерный паттерн ТСПУ: пакеты уходят, но ничего не возвращается.

```
[probe] wg0  endpoint 185.x.x.x:51820
  tx_bytes: 48320 (+48320)  rx_bytes: 0 (+0)
[probe] ТСПУ pattern detected — rx stalled, tx growing
[probe] skipping endpoint 185.x.x.x:51820
[probe] trying next endpoint: 194.x.x.x:51820  [ROUTERS tag]
  tx_bytes: 1240 (+1240)  rx_bytes: 9870 (+9870)
[probe] endpoint OK — activating
```

При выборе эндпоинта в HideMyName приоритет отдаётся серверам с тегом **ROUTERS** — они применяют серверные патчи, специально направленные на обход ТСПУ.

## Эскалационный путь при тяжёлой блокировке

Если WireGuard полностью не проходит через провайдера, инструмент поддерживает последовательную эскалацию:

1. **WireGuard** — стандартный путь
2. **Cloudflare WARP** через wgcf — меняет сигнатуру трафика
3. **Xray VLESS+Reality** — TLS-камуфляж под легитимные HTTPS-соединения
4. **AmneziaWG** — обфусцированный WireGuard с рандомизацией заголовков

В режиме демона переход между уровнями происходит автоматически по результатам зондирования.

## Основные команды

```bash
# Установка
git clone https://github.com/VladiBerez/openwrt-pbr-vpn
cd openwrt-pbr-vpn
pip install -r requirements.txt
cp config.example.yml config.yml

# Ручное зондирование эндпоинтов
python pbr.py probe

# Обновить nft-множество (DoH-резолв + push на роутер)
python pbr.py update

# Запустить сторожевой демон
python pbr.py daemon

# Запустить Web UI
cd ui && npm install && npm run dev
```

Конфиг — YAML-файл с реквизитами SSH-подключения к роутеру, списком VPN-провайдеров и доменами для маршрутизации.

## Требования и статус

- Python 3.10+
- OpenWrt с nftables (23.05+)
- WireGuard или OpenVPN на роутере

Проект в активной разработке, MIT-лицензия. Основной сценарий — роутер под управлением OpenWrt с WireGuard, хост-машина в той же сети.
